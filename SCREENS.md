# Screens: ansible-gui

What each screen does with the system in [DESIGN.md](DESIGN.md): layouts, copy and behaviour that belong to one screen. Tokens, components and states are in DESIGN.md; read it first.

## Run launcher (Run playbook, templates, schedules)
- Launcher groups: the run, template and schedule forms share three titled sections (`form-section`, title `--fs-lg` 700), each a card (`--well`, `--rule` border, `--radius-card`, `--shadow-card`, 20px padding): What to run (playbook, inventory, targets), Variables (what the playbook reads), Tags (which tasks run: a tag for only its tasks, `!tag` to skip them), How to run (mode, Sign in as, then More options: vault password, environment secrets, verbosity). 32px between the cards, 20px between fields inside one.
- Variables (prompts): one group per role inside the Variables card, separated by a hairline (never a card in a card), headed "Role **name** · meta/argument_specs.yml" (name in mono 700), so a field reads as coming from the playbook. Each field: label, then the variable name in muted mono 12px; required options shown, the rest under "N more optional variables". Empty means "send nothing": selects start with "Not set here", and the role's default is in the help line, never a value or placeholder. Bool and single choice are selects; multiple choice is inline checkboxes; lists and dicts are mono textareas; `no_log` options are Secret fields. The role's default shown is the one `defaults/main.yml` sets (what the run gets), else the spec's. A Fields / YAML segmented control (head of the card, only when there are fields) shows one or the other, never both: YAML holds the declared values plus anything else; secrets stay fields: in the YAML view they follow the YAML box in a "Secrets · not in the YAML" group that says why (marked `no_log`; the YAML is saved as typed). In Fields, YAML-only variables are named in an "Also sends …" line. Without fields, the card is just the YAML box ("Extra variables").
- Inventory note: under each variable field and under Sign in as (for `ansible_user`), what the inventory sets on the targeted hosts, redrawn with the preview. "**Inventory** sets `large` on all 2 hosts, from group_vars/lab.yml" (label 600 in `--ink`, values mono `--ink`), or per host. Once the field has a value, the note says what it does to the inventory's: "**Replaces** the inventory’s value ~~`root`~~ on all 9 hosts, from group_vars/lab.yml" (or its per-host values), or "**Same as the inventory’s value** on all 9 hosts." A variable field the inventory doesn't set has no note: the Variables card's head says it once, under its intro ("The inventory sets 1 of these 8 variables for these 9 hosts; the note under each says what.", "The inventory sets none of these variables for these 9 hosts.", or "Can’t check what the inventory sets: it didn’t load."). Sign in as, a single field, says "Not in the inventory for these 9 hosts." itself. The notes are decision text: 14px on every width.
- Playbook picker (launcher): the chosen playbook as a field-like button (repo / path in mono 600, what it does in muted 14px, "Change ⌄" in accent), opening a popover list (`--well`, `--radius-card`, `--shadow-pop`, max 420px) of the same rich options; the checked one is tinted. It is a radio group underneath; choosing closes it, Escape or a click outside closes it.
- Environment secrets (launcher, command, template and schedule forms): a chip field under More options, after the vault password. Nothing is picked on a new run; a run gets the ones picked and no other. The summary line of More options names them ("also $ENROLL_TOKEN"). Shown only when there are secrets to pick.
- Launcher sidebar: from 1280px the preview panel (host count, the Run button, the inventory values the run replaces, then the targeted hosts) is a sticky column beside the form (680px form, 280–340px column, 40px apart). It never scrolls on its own: taller than the window, it moves with the page and stops once its end is in view, above its Run button (app.js sets a negative sticky top), which floats at the bottom right as below 1280px, with the same 88px clear below the form. The Run button's help line adds "Replaces inventory values for N variables, listed below." when there are any, in Dry run and Apply alike. Replaced values are checked on every targeted host and listed by variable ("Replaces inventory values · N variables", a micro label), at most five, the rest under "N more variables": the name in mono 600, the run's value under it in mono 600 `--accent-ink` (the winning source's look), then, indented behind a 1px `--rule-strong` line, each value it replaces in three lines: the old value struck through in `--ink-muted`, its file (or "N files") in muted mono, and the host it was on, or "N hosts ⌄" folding their chips (at most three old values, the rest under "N more values"). Hidden text says "now" and "replaces" for screen readers. A value the same as the inventory's is not a replacement. Variables that replace nothing are one help line ("Also sets build_size, without changing an inventory value."). When nothing is replaced it names them: "The run sets `build_host` without changing any inventory value on these hosts.", and when the inventory didn't load, "Can’t check for overrides: the inventory didn’t load." instead. Last, "Hosts · N": every targeted host as a chip, up to 24. Below 1280px it sits under the form. The values compared (the variable's name, the old value) are decision text, 14px; files and host counts are 12px meta (14px under 640px). The fold chevrons are CSS with empty alt text. The preview is not a live region (it holds the button and long lists): a visually hidden `role="status"` line beside it gets only the count sentence ("9 hosts. Replaces inventory values for 3 variables, listed below."), swapped in out of band. A disabled Run button is described by its reason (`aria-describedby`).
- Run button on narrow screens: below 1280px, where the side panel stacks under the cards, the launcher's primary button floats at the bottom right (full width with a 16px gutter on a phone), above the safe area, with `--shadow-pop`; the form gets 88px of bottom padding so the last field isn't hidden.

## Playbooks
- Playbook list (Run playbook): grouped by repository, the way a variables table is by file: one heading row per repository inside the one card (the same `--code` band: its name in mono 600, linking to the repository, then how many playbooks it has and its commit in muted 12px), and with more than one repository a chip each above the table (`chip-toggle`, "All" first) that narrows the list to the ones picked. A row is the playbook's path in mono, then what it does in muted 14px on one line, max 76ch, cut with an ellipsis where the row ends: the opening paragraph of the top-of-file comment (read across its line wraps), else each role's `galaxy_info.description` (or `argument_specs.main.short_description`), else the play names. The rest of a comment folds under that line (`about-more`): the line ends in a muted 600 toggle that says what it does ("Show 20 more lines", then "Show less"; accent on hover), and opening it unclips the line and shows the rest as written, line breaks and indentation kept, max 60ch of prose per line as before. Every row is one line until someone opens it; the name and the row actions stay at the top of an open row. Above the table, a search ("Find a playbook by name or what it does") with the count beside it: it matches the path and the whole comment, and a row found only by its folded part unfolds while the search stands. The launcher's picker shows the same one line, and the chosen playbook's folded rest sits under the field ("Show 20 more lines from the top of site.yml").
- Pull where the data is used: Run playbook shows a `repo-strip` card (each git playbook repo at its commit, when pulled, any pull error) with "Pull now"; the inventory status strip names each git inventory's commit, and its button reads "Pull and reload" (pull, then re-parse). A failed last pull is a warning banner on the inventory pages.

## Inventory (hosts and groups)
- Inventory pages: Hosts is a full-width table (host in mono 600, address, up to three group chips, OS from facts, last run badge) with a search above that filters by name, address, group or OS; Groups is an indented tree card (name in mono 600, "N hosts · N groups" right-aligned). A host or group page opens on its own, with a breadcrumb (`Hosts / box1`, or `Groups / parent / … / web`) and, for a host, ← previous and next → hosts with "N of M".
- Inventory status strip: above the two panes, `--ink-muted` text: sources (mono), host count, load time, and Reload inventory (secondary) at the end. Hidden when the inventory didn't load; the error panel offers Try again.
- Host header: "connects to X as <user>" names the user a run will actually use: the default account's login, with the inventory's `ansible_user` in a note when it differs.
- Variables table (host and group pages): by file by default. One heading row per source inside the one card (a `--code` band with 16px above its text and 8px below: the path in mono 600 `--accent-ink`, linking to the file and said from where the table's sources part ways (`group_vars/all.yml`, not the checkout's whole path, which is in the tooltip), then what it applies to and how many variables it sets in muted 12px), the source that wins over the others first. Under it each variable is its name, its value and its line in that file (the link), with the "overrides N" stack beside the line when it replaced another source: the file is said once, not on every row. A–Z (`?by=name`; a segmented link switch at the end of the toolbar) is the flat table with the file on every row. Above the table, one chip per source (`chip-toggle`: the path in mono from where the sources part ways, its count in the text face); "All" is first and pressed until one is picked, several can be, and pressed is the Selected look (accent tint, `--accent-ink`, 600) with a tick. The filter reads name, value and file, and the count reads "7 of 41 variables" while anything narrows the table. A table fed by one source shows its heading and neither chips nor switch.

## Credentials
- Accounts: who a run signs in as (login, one of the saved SSH keys, become password), one credential. The launcher's How to run card shows "Sign in as" (a select: name, then "user · key|certificate · become password") under Mode; the vault password sits under More options. The account is the only way to set a run's user, key and become password: no "Connect as", no separate key or become password per run. An SSH key is saved once, under Secrets, with what goes with it (a pasted certificate, or the ssoossh enrollment that fetches one whenever the key signs in), and is picked wherever it signs in: by an account, and by a repository pulled over SSH. Nothing else holds a key: the account form has no key, certificate or enrollment field. The run page says "Signed in as <account> · user <login>" (or "the inventory's user"). The account form is three cards: Account (name, login), SSH key (a select of the saved keys, each with its type, fingerprint and certificate on the second line; "No key" leaves it to the SSH config), Become password. An account whose key was deleted says "key deleted" in the list and "SSH key deleted" in the launcher, and its runs stop before they start. The repository form's "Sign in with" offers only what fits the clone URL, and follows it as it is typed: git tokens for HTTPS, SSH keys for SSH, both (grouped) while there is no URL to go by, nothing for a path on the server.
- Credentials section: three pages under the rail item, as Runs has: Accounts (table: account, user, SSH key, become, updated; "+ Add account" primary), Secrets (one table with a Type column: vault passwords, environment secrets, git tokens, SSH keys, each key's row naming its certificate, the repositories it pulls and the accounts it signs in; a become password is never a secret on its own: it belongs to an account, and older loose ones are listed under Accounts with "Move into an account…"; "+ Add secret" opens the form with a segmented kind switch), SSH settings (SSH config, known hosts). A credential's page is under its list in the rail and its crumb.
- Key note (Secrets): one folded line, "key beside the data", not a standing warning banner.
